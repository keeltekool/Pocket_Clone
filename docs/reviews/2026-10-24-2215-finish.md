### R1 [Important] The "The saved text ends here." notice is missing for some capped pages because the `trimEnd()` added at Gate 2 makes the stored text shorter than the cap
- Where: `src/lib/page.ts:58` (`text.slice(0, MAX_TEXT).trimEnd()`), read at `src/app/read/[number]/page.tsx:30` (`length >= MAX_TEXT`)
- Failure: a page longer than 60,000 chars whose cut lands on a space or right after a `\n\n` is stored with 59,998–59,999 chars. The Reader then sets `truncated = false`, so the reader sees the text stop with no notice and no "Read the rest" link (SPEC §4.6). The repo's own fixture shows it: `scripts/check-page.mjs:33` builds a capped text of 59,998 chars that would show no notice. The flow at `scripts/check-ui-flows.mjs:440` misses it because it writes 60,003 chars straight into the database with SQL, skipping `paragraphs()`.
- Fix: in `page.tsx:30`, use `>= MAX_TEXT - 2` (the trim removes at most 2 chars), or drop the `trimEnd()`, since the Reader's `.filter((p) => p.trim())` already discards a trailing break. Add a check that sends a capped `paragraphs()` result through the same truncation test.
- Confidence: CONFIRMED

### R2 [Important] Leaving a page while a heart save is still in flight can lose the save or show a stale heart
- Where: `src/components/ReaderClient.tsx:60-64` (`back()` calls `history.back()` at once), `:42` (plain `fetch`, no `keepalive`); `src/components/Main.tsx:195-216` together with the card's Read link (`src/components/ItemCard.tsx:77`)
- Failure 1: the owner taps the heart on the Reader, then ← Back right away. The list's GET goes out while the PATCH is still running, so it can read the old row and show the old heart. This is the stale-list problem that Gate 2 I1 was meant to fix.
- Failure 2: a second, queued click has not started its fetch when the page unloads, so it is dropped. The heart looked saved and isn't.
- Failure 3: the same race runs the other way. Heart a card, tap Read at once, and the Reader renders the old value from the server. Every flow waits for the PATCH response before it navigates, so none of this is tested.
- Fix: send the PATCH with `keepalive: true`. In `back()`, `e.preventDefault(); queue.current.then(() => history.back() /* or location.href = "/" */)`.
- Confidence: PLAUSIBLE

## Checked and sound
- **PATCH `/api/items/:id`:** exactly one of `bucketId`/`favourite`; null, primitive and array bodies return 400; non-boolean returns 400; unknown id returns 404; `setFavourite` touches only `favourite`. The proxy requires the session for `/api/*`.
- **Reserved names:** checked after `cleanName` on create and rename. `pocket_suggest_bucket` refuses them. `pocket_list` maps `favourites`/`unsorted` before looking up a bucket. MCP has no write path for the heart.
- **`/read/[number]`:**
  - The session is checked before any database access; logged out gets no title or text, and the page title is "Pocket Clone".
  - `^\d{1,10}$` plus the int32 bound, so `0`, `abc` and out-of-range numbers all 404 with no database error.
  - The not-found page decodes the segment safely and renders it as text. `noindex` comes from the layout. `force-dynamic`, so there is no CDN caching.
- **Hostile page text:** rendered as React text nodes only; no `dangerouslySetInnerHTML` anywhere.
- **Stale poll vs. heart (Gate 1 I1):**
  - The override clears only for polls that started after the PATCH settled.
  - The queue is per card, in click order.
  - A 401 goes through the shared `api` path to the login screen.
  - A 401 on the Reader heart shows the login form.
- **`paragraphs()`:** block and inline handling, whitespace collapsed, empty paragraphs dropped. Readability gets the identity serializer; the body fallback is kept; x.com stays one paragraph.
- **Favourites view:** `inView`, counts, `/?view=favourites` in the URL and on the server; un-hearting inside a search removes the card (Review Focus 2).
- **UI:** Sidebar/MobileSheet row order. Heart opacity rules for desktop, touch and 820 px tablet are covered by flows. The Reader grid is 220/260 px, the type sizes match the spec, `wrap-anywhere` stops sideways scroll at 375, and the rail is sticky.
- **Scope:** no out-of-scope features, no stray files. The migration is additive and idempotent.
